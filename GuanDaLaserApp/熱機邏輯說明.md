# 熱機（冷開機就緒）邏輯說明

> 本文件整理 daemon 模式下，從啟動到可穩定出光所經過的全部「熱機 / 就緒把關」機制。
> 目的：讓維護者理解「為何冷開機第一發（尤其 board 4）會不出光」以及程式目前做了哪些層層防護。
>
> 所有邏輯都在 [`Form1.cs`](Form1.cs) 的 `InitializeBoardAuto`（初始化階段）與 `RunDaemonSpec`（每發打標階段）兩條路徑。

---

## 問題背景

冷開機後，daemon 模式**第一發打標（最常見 board 4，init 順序最後、IP `10.0.0.5`）會不出光，從工作管理員結束 daemon 重啟一次才正常**。

經多輪診斷，確認「不出光」其實是**三個獨立層次**的問題疊加，任一層沒就緒都會造成「StartMarking 回 0（假成功）但雷射不發射」：

| 層次 | 症狀 | 根因 |
|------|------|------|
| **引擎層** | 該板根本沒有打標引擎 | `InitialExt` 非同步啟動 `MM27Dx64.exe`，冷開機連續對 4 板呼叫時後面幾板來不及啟動（啟動競態） |
| **連線層** | 振鏡不動 / 回 rc=1/9 | 乙太網 socket 通 ≠ EMC6 卡韌體 ready；socket 很快通但卡沒真正起來 |
| **雷射致能層** | 振鏡有完整掃描、但雷射不發射 | 雷射 enable 旗標在 init 設過，但被後續 `ResetFile` / 參數套用等操作清掉 |

> ⚠ 關鍵認知：**「連線 ready」「引擎 ready」「雷射致能」是三件獨立的事**。
> 只解決其中一層，另外兩層仍會造成不出光——這就是「為何已暖機仍未出光」的答案。

---

## 熱機時序總覽

```
daemon 啟動
   │
   ├─[初始化階段] InitializeBoardAuto  ← 一次 init 全部板
   │     for 每塊板 i:
   │        建立 OCX 控件
   │        ① InitialExt(cfg)
   │        ② WaitForMarkingEngines  ← 機制 1：等引擎 process 起來（序列化）
   │           └ 逾時 → 重試一次 InitialExt
   │        SetDesktop / MarkStandBy / Redraw
   │        MMEdit.InitialExt(cfg)
   │
   │     ③ WaitForCardsConnected      ← 機制 2 + 機制 3：等卡穩定連線 + 暖機
   │
   │     daemon /health 就緒 ──────────────► 前端開始送命令
   │
   └─[每發打標階段] RunDaemonSpec（每條 /cmd 命令）
         ④ IsCardConnect 把關          ← 機制 4：這發的板沒連上就擋下
         建立內容（AddLine / QR）
         ⑤ EnableLaser(1)              ← 機制 5：每發打標前重新致能雷射
         MarkStandBy → StartMarking
```

## 五個熱機機制逐項說明

### 機制 1｜引擎啟動序列化（`WaitForMarkingEngines`）

**解決層次：引擎層**

`InitialExt` 會**非同步**啟動該板的 EZDrawPlatform 打標引擎 process（`MM27Dx64.exe`，每板一個，正常 4 板 = 4 個）。冷開機時連續對 4 板呼叫 `InitialExt`，系統忙碌，後面幾板的引擎**來不及啟動**→ 該板沒有引擎 → 打標靜默不出光。

**做法**（[`Form1.cs:1880-1899`](Form1.cs#L1880)）：每板 `InitialExt` 前先記下目前引擎數，`InitialExt` 後**輪詢等引擎數 +1**（把引擎啟動序列化），逾時 8 秒未起就**重試一次** `InitialExt` 補救。

| 參數 | 值 | 說明 |
|------|----|------|
| `EngineSpawnTimeoutMs` | `8000` ms | 單板引擎啟動逾時；夠冷開機起來，又不致 4 板累加撐過前端 60s /health 逾時 |
| 引擎 process 名 | `MM27Dx64` | 工作管理員顯示為「EZDrawPlatform MFC Application」 |

相關 helper：[`CountMarkingEngines`](Form1.cs#L1942)（回目前引擎數，查詢失敗回 -1 → 不阻擋初始化）、[`WaitForMarkingEngines`](Form1.cs#L1951)（輪詢等達標）。

> 註：引擎計數是**全機台**的，會含其他 MarkingMate 實例的引擎，故一律用「本板 `InitialExt` 前後的差值 +1」判定，而非絕對數量。

---

### 機制 2｜卡連線穩定確認（`WaitForCardsConnected`）

**解決層次：連線層**

舊行為的坑：**只要 `IsCardConnect() != 0` 一次就放行**。但冷開機時乙太網 socket 很快就通（`IsCardConnect` 立刻回非 0），EMC6 卡內部的控制通道卻還沒 ready。

**做法**（[`Form1.cs:2016-2072`](Form1.cs#L2016)）：改為**連續多次都讀到非 0** 才算某板連上，濾掉「剛通但不穩」的瞬間。中途掉線則穩定計數歸零、重新累計。

| 參數 | 值 | 說明 |
|------|----|------|
| `PollMs` | `200` ms | 輪詢間隔 |
| `StableTicks` | `5` 次 | 連續非 0 的次數（5 × 200ms = 穩定 1 秒）才算連上 |
| `overallTimeoutMs` | `40000` ms | 所有板一起輪詢的總逾時 |

**非致命**：逾時未連線只印警告、**不阻擋 daemon 啟動**（其他板仍可用；且有機制 4 + 前端重試補上）。

---

### 機制 3｜全板連上後固定暖機（`WarmupMs`）

**解決層次：連線層（韌體就緒緩衝）**

即使所有板都「穩定連上」，最慢的卡韌體仍可能需要一點時間完成內部初始化。故在 `WaitForCardsConnected` 內，**所有板都穩定連上後，再固定暖機一段時間才回**（[`Form1.cs:2054-2062`](Form1.cs#L2054)）。

| 參數 | 值 | 說明 |
|------|----|------|
| `WarmupMs` | `3000` ms | 全部板連上後額外暖機延遲，給最慢的卡韌體把控制通道帶起來 |

> 這是冷開機時 daemon `/health` 會「多等約 3 秒」才就緒的來源——以多等換穩定出光。

---

### 機制 4｜每發打標前的連線把關（`IsCardConnect`）

**解決層次：連線層（執行期）**

機制 2/3 是啟動時的一次性把關；機制 4 是**每一條 `/cmd` 命令**派發前再檢查一次目標板的 `IsCardConnect()`（[`Form1.cs:323-333`](Form1.cs#L323)）。

- 針對「最後初始化、連線最慢的板」：即使機制 2 逾時放行，這裡每條命令仍會擋住未連線的板。
- 卡未連接直接回 **`exitCode 9`**（卡未連接），不打沒 ready 的板，由前端重試補上。

---

### 機制 5｜每發打標前重新致能雷射（`EnableLaser`）

**解決層次：雷射致能層**

診斷已確認：冷開機時 board 4 **振鏡有完整掃描**（`StartMarking` rc=0、耗時數秒）**但雷射不發射**，重啟後才正常 = **雷射致能狀態在該板未設起**。致能可能在 init 設過，但被後續 `ResetFile` / `SetPreviewMode` / 參數套用等操作清掉。

**做法**（[`Form1.cs:432-438`](Form1.cs#L432)）：在**每次打標、`StartMarking` 前**明確呼叫一次 `EnableLaser(1)`，貼近發射時機，把可能被清掉的致能重新設起。

- `EnableLaser` 已證實支援（rc=0）、不會彈對話框。
- 診斷 log（`@cold-diag`，寫到 `marking-daemon.log` 的 stderr）：
  - `>>> EnableLaser(1) rc=... @cold-diag`
  - `>>> StartMarking(N) rc=... @cold-diag`
  - `>>> mark done @...ms @cold-diag`

**致能失敗回報**：正式打標（mode 4）時若 `EnableLaser(1)` 回非 0 或拋例外，即**中止、不呼叫 `StartMarking`**，回 `exitCode 10`（雷射致能失敗），logs 帶 rc 與例外訊息。紅光預覽（mode 3）不出雷射，致能失敗不擋。

## 補充：相關但不屬於「就緒」的機制

### MM27Dx64 殘留清理
- **GUI 初始化前**：殺殘留 `MM27Dx64.exe`（[`Form1.cs:663-682`](Form1.cs#L663)）。
- **結束時**：`CleanupMM27Dx64OnExit`，僅在「沒有其他 MarkingMate 實例」時才殺，避免動到並行實例正在用的引擎（[`Form1.cs:246-266`](Form1.cs#L246)）。
- 註：**daemon 的 `InitializeBoardAuto` 開頭並未主動殺殘留**（靠機制 1 的差值判定與重試處理引擎數）。

### 打標逾時估算（`EstimateMarkTimeoutMs`）
與熱機無關，但影響「線段多 / 低速 / 多重複」時會不會被誤判 timeout。動態估算、夾在 **[60s, 570s]**（[`Form1.cs:1972-1999`](Form1.cs#L1972)）。

## 冷開機排查指引

打開 `marking-daemon.log`，依序確認每一層是否就緒：

1. **引擎層**：有無 `[Board N] EZDrawPlatform 引擎已就緒` 或 `⚠ 引擎未在 8000ms 內啟動`。
2. **連線層**：有無 `[Board N] 控制卡已連線且穩定` 與 `[Daemon] 暖機完成，控制卡就緒`。
3. **致能層**：打標時的 `>>> EnableLaser(1) rc=0`（rc=0 才是致能成功；非 0 時前端會收到 `exitCode 10`）。
4. **打標層**：`>>> StartMarking(4) rc=0` 且 `>>> mark done`。

若 1~4 都 OK 卻仍不出光，則**不是時序問題**，往硬體 / 網路查：該板 IP 的雷射卡電源、網路線、switch（主表 `Drivers\EMC6\DevIPAddress.ini`：`DEV3` = board 4）。
