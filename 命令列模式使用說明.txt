===========================================
MarkingMate Multi-Board 命令列模式使用說明
===========================================

版本：3.0
更新日期：2026-07-17

主要變動 (v2.0 → v3.0)：
  - exe 名稱由 WindowsFormsApp1.exe 改為 MarkingMate.exe
  - 新增 Daemon / Client 模式（多板並行的正確做法）
  - 新增 QR Code 打標（含 QRCODE_白底 反相雙圖層）
  - 新增 DXF 檔案載入、Wobble 線寬、紅光預覽
  - 新增 雷射參數（power/speed/freq/pulse-width/repeat）與工作區覆寫
  - QRCODE_白底 預設值同步 GUI：15×15mm、外框 2、QR 功率 80、
    QR 速度 1000、矩形功率 100、矩形速度 800

===========================================
一、程式支援的三種執行模式
===========================================

1. GUI 模式（原有功能）
   - 不帶任何參數啟動：MarkingMate.exe
   - 顯示完整圖形介面，可手動操作全部頁籤

2. 命令列 單命令模式（Mode A，適合一次性動作）
   - 帶參數啟動：MarkingMate.exe [選項]
   - 該 process 自己 init OCX、執行完動作、退出
   - 限制：一台機器同時只能跑一個 CLI 單命令（SDK OCX 為 process-global）
   - 若已有 daemon 在跑，會被自動轉發成 Client（見下方）

3. Daemon + Client 模式（Mode B，推薦，多板可並行）
   - Daemon：一次 init 全 4 板，聽 HTTP localhost:19527
     啟動：start "" MarkingMate.exe --daemon
   - Client：把命令 POST 進 daemon，daemon 在同一 process 內派工
     用法：MarkingMate.exe --client [其他選項]
   - 多個 client 可同時發到不同板做 in-process 並行

===========================================
二、命令列參數（完整列表）
===========================================

--- 基本 ---
  --help, -h, /?             顯示說明訊息（app 內建 CommandLineArgs 版本）
  --board <0-3>, -b <0-3>    晶片板編號 0-3 (預設: 0)
  --config <path>, -c <path> 配置路徑 (預設: /cfg_config_MM1)
                             建議跟 --board 對應：
                               --board 0 → /cfg_config_MM1
                               --board 1 → /cfg_config_MM2
                               --board 2 → /cfg_config_MM3
                               --board 3 → /cfg_config_MM4

--- 工作區 ---
  --workspace <mm>, -w <mm>  工作區寬高相等 (預設: 150)
  --workspace-w <mm>         工作區寬 W mm（與 --workspace 二擇一）
  --workspace-h <mm>         工作區高 H mm（可與 W 不同；DXF 縮放取 min(W,H)）

--- 內容（三擇一或組合）---
  --line <x1,y1,x2,y2>, -l   單一線段 (mm)，原點為工作區中心
  --lines "<清單>"           多條線段，分號分隔："x1,y1,x2,y2;x1,y1,x2,y2;..."
  --dxf <path>, -d <path>    載入 DXF 檔案（手動解析 LINE entity）
  --qrcode <content>, -qr    QR Code 內容
  --qr-width <mm>            QR 寬 mm。單獨 QR 預設 10；--qr-whitebg 未帶時走 15（與 GUI 同）
  --qr-height <mm>           QR 高 mm。單獨 QR 預設 10；--qr-whitebg 未帶時走 15（與 GUI 同）
  --qr-invert                QR 反相（單獨 QR 用；白底反相請改用 --qr-whitebg）
  --qr-whitebg               白底反相 QR：矩形白底 + 反相 QR 雙圖層
                             *** 詳見第三節 QRCODE_白底 ***
  --qr-border <cells>        白底 QR 外框單元數。--qr-whitebg 未帶時走 2（與 GUI 同）；
                             單獨 QR schema 預設 5

--- 雷射參數（不指定 = 用板現行預設）---
  --power <0-100>, -p        功率 % 0-100
  --speed <mm/s>, -s         速度 mm/s
  --freq <kHz>, -f           頻率 kHz
  --pulse-width <ns>, --pw   脈波寬度 ns
  --repeat <n>, -r           雷射次數

--- Wobble 線寬（線段類專用） ---
  --wobble-width <mm>, --wobble  線條加粗寬度 mm (預設: 0.5)
  --wobble-overlap <%>           重疊率 % (預設: 50)
  --wobble-speed <mm/s>          擺動速度 (預設: 5026.55)

--- 動作 ---
  --mark, -m                 執行打標（缺此僅建立內容不打）
  --preview <outline|full>   紅光預覽模式（不出雷射，需搭配 --mark）
                               outline = 外框，full = 全路徑（預設 full）
  --preview-speed <mm/s>     預覽速度
  --preview-time <秒>        預覽持續秒數 (預設: 15)

--- Daemon / Client ---
  --daemon                   啟動常駐 daemon（一次 init 全 4 板）
  --client                   Thin client：把命令 POST 到 daemon
  --port <N>                 Daemon 監聽 port / client 連接 port (預設: 19527)
  --shutdown                 (搭配 --client) 通知 daemon 結束

===========================================
三、QRCODE_白底（重要，最常用的 QR 工作流）
===========================================

「白底反相 QR」= 一個雕實心白底矩形 + 一個反相 QR，兩層合在一起，
                 讓黑色鋼鐵表面呈現「白底 + 反相黑碼」的高對比 QR。

3.1 GUI 對應
    在「6. QRCODE」頁籤的「QRCODE_白底」GroupBox：
      矩形速度: 800     矩形功率: 100
      QR 速度:  1000    QR 功率:  80
      QR 長:    15      QR 寬:   15
      外框單元: 2       X:       0     （X 為矩形額外加大量）
      打標:     全部    序號:    自動遞增

3.2 CLI 對應（最簡形式）
    只需帶 --qrcode 內容 + --qr-whitebg，其餘由後端 WhiteBgQRParams
    寫死預設補齊（值同 GUI GroupBox 目前設定）：

    MarkingMate.exe --client --board 0 --config /cfg_config_MM1 ^
      --qrcode "1234567" --qr-whitebg --mark

3.3 CLI 對應（完整顯式；等同 GUI 目前設定）
    MarkingMate.exe --client --board 0 --config /cfg_config_MM1 ^
      --qrcode "1234567" --qr-whitebg ^
      --qr-width 15 --qr-height 15 --qr-border 2 ^
      --power 80 --speed 1000 --mark

3.4 各板對應範例
    板 1：--board 0 --config /cfg_config_MM1
    板 2：--board 1 --config /cfg_config_MM2
    板 3：--board 2 --config /cfg_config_MM3
    板 4：--board 3 --config /cfg_config_MM4

3.5 寫死於後端、CLI 無法覆寫的部分
    矩形速度 800、矩形功率 100、矩形 FillStyle=3、FillTimes=4、
    向內填滿、StartAngle=90、StepAngle=45、矩形 Freq=80、
    PulseWidth=250 —— 位於 Form1.cs BuildWhiteBgQR / WhiteBgQRParams。
    若要調整需改 code + 重新編譯。

3.6 CLI 可覆寫的 QR 圖層參數
    --qr-width / --qr-height / --qr-border  → QR 尺寸與外框
    --power / --speed                       → QR 圖層雷射參數
    （矩形圖層的功率/速度不能透過 CLI 覆寫）

===========================================
四、結束代碼 (Exit Code)
===========================================

CLI 單命令模式 / Daemon 內動作：
  0  - 成功
  1  - 初始化失敗（含 IP 主表未填、SDK 部署權限不足）
  2  - 繪圖失敗（含板已被其他 CLI process 佔用時的 -2）
  3  - 打標失敗
  4  - 參數錯誤
  5  - 板正忙（daemon 收到 client 命令但該板正在打標/預覽）
  -3 - 已有 daemon 在同 port 運行

Client 模式（僅 client process 自身）：
  6  - 無法連線到 daemon（未啟動或 port 不對）
  7  - Client 例外（HTTP 傳輸或解析失敗）

批次檔範例：
    MarkingMate.exe --client --board 0 --qrcode "TEST" --qr-whitebg --mark
    if %ERRORLEVEL% EQU 0 (
        echo 成功
    ) else (
        echo 失敗，錯誤碼：%ERRORLEVEL%
    )

PowerShell 範例：
    & "MarkingMate.exe" --client --board 0 --qrcode "TEST" --qr-whitebg --mark
    if ($LASTEXITCODE -eq 0) {
        Write-Host "成功"
    } else {
        Write-Host "失敗，錯誤碼：$LASTEXITCODE"
    }

六、C# 程式呼叫範例
===========================================

using System.Diagnostics;

// 6.1 單命令模式
public int ExecuteMarking(int board, string qrContent)
{
    var psi = new ProcessStartInfo
    {
        FileName = @"C:\Path\To\MarkingMate.exe",
        Arguments = $"--client --board {board} --config /cfg_config_MM{board + 1} " +
                    $"--qrcode \"{qrContent}\" --qr-whitebg --mark",
        UseShellExecute = false,
        CreateNoWindow = true,
        RedirectStandardOutput = true,
        RedirectStandardError = true
    };

    using (var process = Process.Start(psi))
    {
        process.WaitForExit();
        return process.ExitCode;
    }
}

// 使用
int rc = ExecuteMarking(0, "SERIAL-001");
if (rc == 0) Console.WriteLine("打標成功");
else Console.WriteLine($"失敗 exitCode={rc}");

七、Python 程式呼叫範例
===========================================

import subprocess

def execute_qr_whitebg(board: int, content: str, exe: str = r"C:\Path\To\MarkingMate.exe") -> int:
    """
    透過 CLI Client 呼叫 MarkingMate daemon 打白底反相 QR

    Args:
        board: 晶片板 0-3
        content: QR 內容
        exe: MarkingMate.exe 完整路徑

    Returns:
        int: 結束代碼 (0=成功)
    """
    args = [
        exe, "--client",
        "--board", str(board),
        "--config", f"/cfg_config_MM{board + 1}",
        "--qrcode", content,
        "--qr-whitebg",
        "--mark",
    ]
    result = subprocess.run(args, capture_output=True, text=True, encoding="utf-8")
    return result.returncode

# 使用
rc = execute_qr_whitebg(0, "SERIAL-001")
print(f"打標成功" if rc == 0 else f"失敗 exitCode={rc}")

===========================================
八、雷射頭 IP 設定（初始化前置條件）
===========================================

IP 主表位置：
    WindowsFormsApp1\Drivers\EMC6\DevIPAddress.ini
    DEV0 → MM1 / CARD0
    DEV1 → MM2 / CARD1
    DEV2 → MM3 / CARD2
    DEV3 → MM4 / CARD3

初始化流程（含 CLI）：
    1. 驗證主表 DEV0~DEV(--board) 已填入有效 IP，缺值即中止
    2. 依 CARD 對應把主表 IP 同步到各 EMC6_MMx\DevIPAddress.ini 的 DEV0
    3. 部署 Drivers\EMC6\ 到 MarkingMate 安裝路徑
    4. 部署 config\config.ini 與 config_MMx.ini、cfg\*.cfg

若主表 IP 未填或部署失敗：
    CLI 在 stderr 列出具體原因，ExitCode = 1
    Daemon 啟動時同樣校驗，缺 IP 拒絕啟動

IP 編輯：目前僅 GUI 模式支援（在「1. 連接設定」頁填後按「儲存IP」）

===========================================
九、注意事項
===========================================

9.1 為什麼要用 Daemon？
    SDK OCX（AxMMMarkx64 / AxMMEditx64）為 process-global 註冊，
    兩個 process 同時 init 會撞驅動全域鎖，症狀：
        「Please initial MMMark_1 OCX first!」
    且壞在驅動層，重啟 daemon 也接不回來，通常需重開機。
    因此偵測到已有 daemon 時，程式會自動把單命令模式轉發成 Client。

9.2 執行時間
    - Daemon 啟動：3-6 秒（4 板全 init）
    - Client 單次命令：< 1 秒往返 + 打標時間
    - QRCODE_白底 打完約 30-90 秒（視內容複雜度）
    - 建議超時：一般 --mark 90 秒；DXF 大檔 300 秒

9.3 座標系統
    - 原點 (0,0) 在工作區中心
    - X 軸：右為正
    - Y 軸：上為正（SDK 內部座標）
    - 單位：毫米 (mm)
    - 有效範圍：依 --workspace 設定（預設 150 → -75 到 +75）

9.4 序號自動遞增
    - Steel Quest3 / QRCODE_白底 各自有 counter 檔：
        counter.txt          （Steel Quest3）
        counter_whitebg.txt  （QRCODE_白底）
    - 每次執行 +1，跨天不重置
    - 檔案位於 exe 同目錄

9.5 GUI 與 CLI 共享後端
    - QRCODE_白底 打標邏輯由 GUI btn 與 CLI 共用 BuildWhiteBgQR
    - 若 GUI GroupBox 調整參數，CLI 預設值需同步更新（見 WhiteBgQRParams）

===========================================
十、疑難排解
===========================================

Q1: 執行後立即退出，無任何反應
A: 檢查參數格式與引號跳脫，用 --help 查看說明

Q2: ExitCode = 1（初始化失敗）
A: - 檢查 IP 主表 DevIPAddress.ini 是否已填
   - 檢查 MarkingMate SDK 是否已安裝
   - 用 GUI 模式測試初始化能否成功
   - 檢查是否需以管理員身分執行（首次部署 config 到 Program Files）

Q3: ExitCode = 2（繪圖失敗 / 板被佔用）
A: - 檢查座標是否在工作區內
   - 座標格式是否正確（逗號分隔）
   - 是否已有 CLI 單命令在跑同一板

Q4: ExitCode = 3（打標失敗）
A: - 檢查硬體連接與控制卡 IP
   - GUI 模式「測試連接」是否 OK
   - 檢查雷射頭 shutter 是否開啟

Q5: ExitCode = 4（參數錯誤）
A: - --board 範圍是否 0-3
   - QR 內容是否含特殊字元需引號跳脫
   - --workspace-w / --workspace-h 是否為正數

Q6: ExitCode = 5（板正忙）
A: - Daemon 該板正在打標/預覽，等該任務結束再試
   - 或呼叫另一板

Q7: ExitCode = 6（Client 無法連線 daemon）
A: - Daemon 未啟動：start "" MarkingMate.exe --daemon
   - 使用了非預設 port：帶 --port <N>
   - 防火牆阻擋 localhost 19527（少見）

Q8: ExitCode = 7（Client 例外）
A: - HTTP 傳輸中斷，通常伴隨 daemon crash
   - 檢查 daemon 視窗是否還在
   - 重啟 daemon

Q9: QR 打出來位置偏移
A: - 檢查 config 對應板：--board N 需搭配 --config /cfg_config_MM(N+1)
   - 檢查工作區大小與雷射頭校正

Q10: 白底 QR 打完後表面反光看不到碼
A: - 這是預期：白底反相 QR 需要「有髒污/氧化底層」時才明顯
   - 若表面過亮/過暗，可調 QR 圖層 --power / --speed（矩形不動）

===========================================
十一、技術細節
===========================================

實作方式：
    - Application 類型：WinExe（AxHost / OCX 需要 STA + Message Pump）
    - CLI 模式視窗以 Opacity=0 + Minimized 建立，Application.DoEvents 保持訊息
    - Daemon 內建 HttpListener，POST /cmd 派工到對應板
    - CORS 開放 * 供網頁呼叫
    - 4 個 AxMMMarkx64 + 4 個 AxMMEditx64 共存於同 process（in-process parallel）

Mutex 命名（同時只能一個實例）：
    - GUI 模式：MarkingMateMulti_SingleInstance
    - Daemon 模式：MarkingMateMulti_Daemon
    - CLI Board N 模式：MarkingMateMulti_Board<N>
    - Client 模式：不持 Mutex（因為不 init SDK）

檔案位置：
    exe：           MarkingMate.exe (原 WindowsFormsApp1 專案，OutputName)
    序號 counter：  exe 同目錄 counter.txt / counter_whitebg.txt
    QRCode 素材：   exe 同目錄 QRCodePara\
    Config：        C:\Program Files (x86)\MarkingMate\ 底下

限制：
    - x64 平台，.NET Framework 4.7.2/4.8
    - 需要 Windows 視窗環境（無 headless）
    - 需要 MarkingMate SDK 與 OCX 註冊
    - 一台機器同時只能有一個 Daemon
    - QR-only 命令僅 --qr-whitebg 支援白底反相（單獨 QR 無反相白底）
