## 🎯 快速解決方案

### 第一步：測試範例程式

**執行：**
```
C:\Program Files (x86)\MarkingMate\sdk\ocx\CSharp_example\VS2017\LoadFile\LoadFile\bin\x64\Release\LoadFile.exe
```

**結果判斷：**

## 解決方案 A：註冊 OCX（範例程式也失敗時）

### 選項 1：使用自動腳本

1. **以系統管理員身分**執行 `RegisterAndDiagnose.ps1`
   ```powershell
   # 右鍵 → 以系統管理員身分執行 PowerShell
   Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
   .\RegisterAndDiagnose.ps1
   ```

### 選項 2：手動註冊（最可靠）

1. **以系統管理員身分**開啟命令提示字元
   - 按 `Win + X`
   - 選擇「命令提示字元（系統管理員）」

2. **切換到 DLL 目錄**
   ```cmd
   cd "C:\Program Files (x86)\MarkingMate\sdk\ocx\CSharp_example\VS2017\LoadFile\LoadFile\bin\x64\Release"
   ```

3. **註冊每個 DLL**（逐一執行）
   ```cmd
   regsvr32 MMEditx64Lib.dll
   ```
   - 應該會看到：「DllRegisterServer 在 MMEditx64Lib.dll 成功」
   - 點擊「確定」

   ```cmd
   regsvr32 MMMarkx64Lib.dll
   ```
   - 應該會看到：「DllRegisterServer 在 MMMarkx64Lib.dll 成功」
   - 點擊「確定」

   ```cmd
   regsvr32 MMStatusx64Lib.dll
   ```
   - 應該會看到：「DllRegisterServer 在 MMStatusx64Lib.dll 成功」
   - 點擊「確定」

4. **驗證註冊**
   - 重新執行範例程式
   - 應該能正常啟動

## 解決方案 A+：四顆雷射頭設定（MM1~MM4）

每顆雷射頭都需要齊備這四項，缺一個 `InitialExt()` 就會炸：

| 項目 | 來源（專案內，可進版控） | 部署目標（MarkingMate 安裝目錄） |
|---|---|---|
| **卡片 IP 主表（單一來源）** | `WindowsFormsApp1\Drivers\EMC6\DevIPAddress.ini`（DEV0~DEV3 = CARD0~CARD3 = MM1~MM4） | （隨整個 EMC6 共用目錄部署） |
| **EMC6 共用目錄（含驅動、cfg、主表）** | `WindowsFormsApp1\Drivers\EMC6\` | `C:\Program Files (x86)\MarkingMate\Drivers\EMC6\`（**遞迴複製整個目錄**） |
| 共用 config.ini | `WindowsFormsApp1\config\config.ini` | `C:\Program Files (x86)\MarkingMate\config.ini` |
| 雷射頭 config | `WindowsFormsApp1\config\config_MMx.ini` | `C:\Program Files (x86)\MarkingMate\config_MMx.ini` |
| 各 MMx IP 檔（DEV0 由主表依固定 CARD 對應同步） | `WindowsFormsApp1\Drivers\EMC6_MMx\DevIPAddress.ini` | `C:\Program Files (x86)\MarkingMate\Drivers\EMC6_MMx\DevIPAddress.ini` |
| 雷射頭 cfg 目錄（含 `DEFAULT CARD`、`MultiCard`、`MultiSYN*` 多卡同步參數） | `WindowsFormsApp1\Drivers\EMC6_MMx\cfg\*.cfg` | `C:\Program Files (x86)\MarkingMate\Drivers\EMC6_MMx\cfg\*.cfg` |
| 鏡頭 / 校正檔 | （由現場校正產生，因鏡頭而異） | `C:\Program Files (x86)\MarkingMate\Lens_MMx\default.*` |
| OCX 註冊 | — | 由 `ELOCXRegister.exe` 完成（見解決方案 A） |

> **CARD 對應（固定）**：MM1→CARD0、MM2→CARD1、MM3→CARD2、MM4→CARD3。
> 主表 `EMC6\DevIPAddress.ini` 是 IP 的**單一來源**；UI 讀寫的就是它，初始化時會把 DEV0~3 同步到各 `EMC6_MMx\DevIPAddress.ini` 的 DEV0。

> **設計**：專案內 `config\` 與 `Drivers\` 是真實來源（可 commit）；
> 程式按下「初始化」會把它們**自動部署**到 MarkingMate 安裝目錄並驗證 IP 是否填齊，
> 任一環節有問題會在 InitialExt 之前以對話框提示並中止，不會讓 OCX 直接拋例外。

### 步驟（建議流程）

1. **註冊 OCX** — 解決方案 A。
2. **填入四顆 IP**：
   - 啟動程式 → 在 UI 四個 IP 欄位填入 MM1~MM4 各自的控制卡 IP → 按「儲存IP」
   - 此動作會寫回 `WindowsFormsApp1\Drivers\EMC6_MMx\DevIPAddress.ini`（專案來源，可進版控）
3. **體檢**（可選但建議）：
   ```powershell
   cd WindowsFormsApp1
   .\CheckMMSetup.ps1                # 檢查 4 顆
   .\CheckMMSetup.ps1 -BoardCount 2  # 只檢查 MM1~MM2
   ```
   會逐項列出來源檔、部署目標、鏡頭、OCX 註冊狀態，並指出阻擋項。
4. **以系統管理員身分**執行程式 → 設定板數 → 按「初始化」
   - 部署到 `C:\Program Files (x86)\MarkingMate\` 需要寫入權限
   - 部署前會自動把舊的 `*.ini` 備份成 `*.ini.bak`，便於還原
5. **校正檔**：`Lens_MMx\default.cor` 等需依各自鏡頭實際校正產生，**四顆不能共用同一份**。

### 程式內如何運作

- [Form1.cs](Form1.cs) 的 `DeployAndValidateLaserHeadConfigs(boardCount, out errorInfo)`，依序執行 5 步：
  1. 從 `Drivers\EMC6\DevIPAddress.ini` 讀 `DEV0~DEV(boardCount-1)`，全部須非空（任一為空就以 MessageBox 中止）
  2. 依固定 CARD 對應（MM1→0、MM2→1、MM3→2、MM4→3）把主表 IP 同步到各 `EMC6_MMx\DevIPAddress.ini` 的 `DEV0`
  3. `CopyDirectoryRecursive` 把 `Drivers\EMC6\` 整個遞迴部署到 `MarkingMateRoot\Drivers\EMC6\`
  4. `CopyWithBackup` 把 `config\config.ini` 部署到 `MarkingMateRoot\config.ini`
  5. 對每片 MMx：`CopyWithBackup` 部署 `DevIPAddress.ini` 與 `config_MMx.ini`，`DeployCfgDirectory` 把 `Drivers\EMC6_MMx\cfg\*.cfg` 複製到 `MarkingMateRoot\Drivers\EMC6_MMx\cfg\`
- `btnInit_Click` 與 `InitializeBoardAuto` 都會在 `InitialExt(...)` 之前呼叫它，
  失敗就以 MessageBox（GUI 模式）或 Debug 訊息（自動模式）回報並 return，OCX 不會吃到髒資料。

> ⚠️ MultiMM SDK 預設範例（`MultiMM_Mark`）只示範到 MM1+MM2。要使用 MM3、MM4 仍須在
> `MultiMMSetting.exe` 中事先建立 `cfg_config_MM3` / `cfg_config_MM4` 兩個內部配置；
> 若沒有建立，`InitialExt("/cfg_config_MM3")` 會失敗。

## 常見錯誤和解決方法

### 錯誤 1：「找不到指定的模組」
**原因：** DLL 依賴項缺失
**解決：**
- 安裝 Visual C++ Redistributable 2017 x64
- 檢查 Windows\System32 中是否有所需的 DLL

### 錯誤 2：「存取被拒」
**原因：** 權限不足
**解決：**
- 以系統管理員身分執行所有註冊命令
- 關閉防毒軟體再試

### 錯誤 3：「模組可能與此 Windows 版本不相容」
**原因：** 平台不匹配
**解決：**
- 確認使用 x64 版本的 DLL
- 確認 Windows 是 64 位元系統
- 確認專案編譯為 x64
